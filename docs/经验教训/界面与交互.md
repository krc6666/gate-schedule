# 分则：界面与交互

本页为有效方法；先读[通则与索引](../需求理解与验收经验.md)。操作是否完成以用户实际看到和做到的结果为准。

<a id="u01"></a>

## U01 显示分组的依据

**检索词**：大件、共享任务、合并、分格、时间重叠、保障窗口、工作窗口、跨日、链式。

**适用**：把多个业务对象合成一格、一组或一段显示。

**易错**：只因底层任务关联就合并，遗漏用户比较的时间/范围；经中间对象把不满足条件的首尾对象连起来；为拆显示而复制或拆坏真实任务。

**做法**：明确用户判断分组所用尺度，将显示条件与任务身份分别核对。按[R02](需求与边界.md#r02)验证不同名称及时间边界、多对象传递、资料缺失；分格后检查共享编辑、缺口、清空与撤销是否仍指向真实任务。

**完成标准**：原误合并被阻止，正常共享保持；两种布局及受影响导出一致，后续编辑不产生重复任务或不同步。

**证据**：[E04 大件显示通用窗口条件](../../history.md#lesson-e04)。航班具体合并条件以spec为准，不推广为所有界面都按航班时间分组。

<a id="u02"></a>

## U02 从陌生使用者的操作出发

**检索词**：规则页、分类、折叠、展开、搜索、增加、减少、删除、独立入口、维护。

**适用**：页面包含多个类别、子页或可持续维护的规则列表。

**易错**：默认全部铺开；把不同规则混在同一入口；只有新增禁用规则，却没有新增接续来源/目标的操作；只摆出当前内容，无法维护。

**做法**：从“找到类别→展开→新增本类条目→增删子项→保存→重新打开”走通；同类控件位置一致，操作命名说明新增的具体对象。折叠/搜索状态与业务设置区分，长期偏好按[D01](数据与配置.md#d01)验证迁移。

**完成标准**：陌生使用者能找到对应类别的独立维护入口；新增、编辑、删除、保存及重新打开可用，宽窄屏操作可见；单纯展开搜索不改变业务规则。

**证据**：[E05 规则页分类、折叠与独立增删](../../history.md#lesson-e05)。默认折叠是该页已确认方案，其他页面按自己的任务评估。
