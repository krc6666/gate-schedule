# 分则：概念与规则关系

本页为有效方法；先读[通则与索引](../需求理解与验收经验.md)。优先级与合法性采用[当前spec](../../spec.md)，下列事件用于发现模型遗漏。

<a id="m01"></a>

## M01 限制的作用范围

**检索词**：专岗、专人专岗、同班、跨班、同一对象、局部、全局、目录过滤。

**适用**：规则只约束某个对象、同一列或某段范围，但影响多个模块。

**易错**：从“同一航班内只出现一次”推导出禁止去其他航班；在编辑目录全局删除只在特定场景受限的岗位。

**做法**：按G02写清受限对象和关联范围，追踪候选、求解、目录、人工编辑及最终校验；分别检查范围内拒绝与范围外允许，其他独立限制另行说明。

**完成标准**：同对象内反例被拒绝，不同对象间在其余条件合法时可操作；目录和最终校验采用相同作用范围。

**证据**：[E02 同航班专岗边界修正](../../history.md#lesson-e02)。

<a id="m02"></a>

## M02 核对精确对象

**检索词**：核验、查验、VIP、优先通道、相近名称、来源岗、目标岗、身份。

**适用**：用户描述与系统名称相近，或不同岗位共用部分文字。

**易错**：把普通核验与VIP查验当成同一岗位；用另一目标或另一日期的成功替代原对象验收。

**做法**：核对用户所指对象、实际配置引用、资格与日期；相近对象分别列明。单变量替换只用于诊断，并记录替换前后，现场身份核对继续查[V01](验证与交付.md#v01)。

**完成标准**：验收直接检查原对象；对照试验和原现场证据清楚区分，不暗中替用户换目标或配置。

**证据**：[E09 26日接续调查中的岗位与日期差异](../../history.md#lesson-e09)。该节为阶段记录，最终兼职结论见[E03](../../history.md#lesson-e03)。

<a id="m03"></a>

## M03 先核对比较的事实

**检索词**：优先留空、优先级、接续、衔接、兼职、占人、次数、硬约束、软偏好。

**适用**：两个规则看似冲突，或用户通过改名解释业务概念。

**易错**：只讨论谁的优先级更高，却把“同人出现两次”等同于“另占两个人”；仅改名称，遗漏模型中的资源含义。

**做法**：分别写明规则作用对象、资源消耗、触发条件及硬限制/软偏好性质；按G02核对是否真在比较同一事实，再用同人合法兼职与另占人手成对验收。具体当前优先级引用spec，不在本页另设权重或保证必接。

**完成标准**：两种资源情形有可区分的结果，资格、禁止与其他合法性独立检查；名称、规则说明、求解和验收含义一致。

**证据**：[E03 接续兼职与另占人手](../../history.md#lesson-e03)、[E01 早期留空理解偏差](../../history.md#lesson-e01)。两节存在先后纠正关系，不能摘取早期一句话覆盖最终确认。
