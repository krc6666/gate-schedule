# 经验教训：通则与检索入口

开发、修改、排错及交付都从本页开始：先读六条通则，再按任务检索分则；涉及多个专题时逐项查阅。具体复盘保留在history，分则只维护可复用方法。适用范围不限于排班。

## 通则：每次必读

<a id="g01"></a>

**G01 用户结果优先。** 先独立写清触发条件、预期结果、作用范围和明确例外，标出自己的假设；每个影响行为的判断都能对应用户原意。实现方案在此之后选择。

<a id="g02"></a>

**G02 分清对象与尺度。** 核对具体对象、身份、次数、人数、时间及限制范围；分别记录容易混同的事实，再判断它们的关系。

<a id="g03"></a>

**G03 从例子提炼通用条件。** 按决定结果的条件实现，并准备能区分两种理解的正反用例；更换姓名、编号或日期后仍应成立。

<a id="g04"></a>

**G04 纠偏先核对自身解释。** 用户指出不符时，对照原话、实现和验收预期，撤掉自己附加的条件；原意重申不记作用户改需求。需要澄清的独立决定按AGENTS处理，其余工作继续。

<a id="g05"></a>

**G05 沿实际操作闭环。** 追踪输入、保存、计算、后续动作、重新打开与原使用入口，按受影响的真实路径验收；局部通过只证明对应局部。

<a id="g06"></a>

**G06 证据与结论匹配。** 区分根因解释、修复效果、自动测试和现场确认。当前业务事实查[spec](../spec.md)，权威顺序按[AGENTS](../AGENTS.md)；历史案例只提供经验和证据。

## 维护与失效处理

1. 新经验先查已有条目。同一原因补证据或改进做法；不同原因才增加条目，不预建空专题。
2. 每条包含稳定编号、检索词、适用情形、易错点、做法、完成标准及证据链接。编号不回收；改标题保留锚点，跨文件移动时原位置保留指向新位置的链接。
3. 通则只收跨专题反复适用的方法；专题细节放分则，事件经过放[history](../history.md)。当前业务规则在spec中维护，经验文档引用它，不另立一套业务结论。
4. 分则默认“有效方法”。被替代条目显式标为“已替代”并链接替代项；保留原案例及纠正关系。历史中的阶段判断不能直接作为今天的规则。
5. 任务开始在现有计划或验收记录中写命中的条目编号与检查点，简单任务可直接落到失败用例；结束只记录检查结果、新证据和必要条目更新，不重复抄写教训。
6. 维护后核对索引、链接、唯一编号、旧内容覆盖和检索示例；文档校验通过只证明知识入口可用，不替代程序或现场验收。
